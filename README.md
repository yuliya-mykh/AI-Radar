# AI Radar — каталог і пошук AI-сайтів

Статичний вебпроєкт на публічному API [freeserp.ai](https://freeserp.ai/docs.php) (`index=sites`, `category=ai`, без ключа й реєстрації). Єдина серверна частина — маленька функція-посередник на Vercel (`api/freeserp.js`), яка пересилає запити до API.

**Демо:** https://yuliya-mykh.github.io/AI-Radar/

## Знайдена проблема в API

API не можна викликати з браузера напряму: сервер freeserp.ai віддає заголовок `Access-Control-Allow-Origin` двічі (`*, *`), а браузери таке блокують — хоча в документації вказано, що CORS відкритий. Те саме з `/api`, `?stats=1` і `/mcp`. Із сервера (curl, Node) API працює нормально.

Рішення в проєкті: функція `api/freeserp.js` на Vercel пересилає запит до API й повертає відповідь з одним коректним заголовком, додаючи кеш на 5 хвилин. Адреса призначення зафіксована, тож це не відкритий проксі. Сайт спершу звертається до посередника, а пряма адреса API лишається запасною — запрацює сама, щойно помилку виправлять.

## Як виконано

Проєкт зроблено через Claude Desktop: ідея, план сайту, код, дизайн і тести — у діалозі з AI, з моїми правками по дизайну та структурі.

## Що зроблено

- **Каталог**: повнотекстовий пошук (`q`) у панелі фільтрів; фільтри за нішею (`ai_categories`), мінімальним DR (`dr_min`), датою появи в індексі (`from_date`), доменною зоною (`tld`), перемикач «лише справжні AI-продукти» (`ai_startups=1`), чотири сортування, пагінація в межах ліміту API (10 000 результатів).
- **Новинки**: стрічка за `went_live`, згрупована по днях, періоди 7/30/90 днів, кнопка «Показати ще».
- **Порівняння**: до 4 сайтів у таблиці (DR, ніші, опис, дати, зона, технологія, вебсервер, обсяг тексту), додавання з картки або за доменом, посилання для поширення `#/compare?d=a.com,b.ai`.
- **Картка сайту** в модальному вікні з усіма полями профілю.
- **Іконки сайтів** у картках: фавікон за доменом (сервіс Google), якщо його немає — кольорова літера.
- **Живі лічильники** та кількість сайтів у кожній ніші з `?stats=1`.
- Стан фільтрів зберігається в адресі — будь-яку добірку можна надіслати посиланням.
- Стани завантаження, порожнього результату й помилки; повтор запиту при 502/збої мережі; скасування застарілих запитів; кеш у памʼяті.
- Мобільна версія: меню-бургер, фільтри у висувній шторці з кнопкою «Показати N сайтів», збільшені зони натискання.
- Адаптивна верстка, світла пастельна тема (рожевий, мʼята, орхідея), шрифт Manrope з Google Fonts, навігація з клавіатури, екранування всіх даних з API.
- План сайту: [PLAN.md](PLAN.md) і сторінка «Про проєкт».

## SEO

Зроблено базове: `title` і опис (свій для кожного розділу), `canonical`, Open Graph і Twitter-розмітка з картинкою `assets/og.jpg`, JSON-LD (`WebSite`), `robots.txt`, `sitemap.xml`, семантична розмітка.

Адреса сайту в цих тегах і файлах — `https://yuliya-mykh.github.io/AI-Radar/`; якщо сайт переїде, її треба замінити в `index.html`, `robots.txt` і `sitemap.xml`.

Обмеження: розділи відкриваються через `#/…`, а картки підвантажуються з API в браузері, тому для пошуковика це одна сторінка без каталогу в HTML. Сайт лежить у підтеці домену, тому `robots.txt` пошуковики не читають — він спрацює лише на власному домені.

## Як запустити

Збірка й залежності не потрібні.

**Публікація на Vercel (рекомендовано).** Імпортувати репозиторій у Vercel (Add New → Project, Framework Preset: Other) — статичні файли й функція з теки `api/` розгортаються самі.

**Локально** — через Vercel CLI, щоб працювала функція-посередник:

```bash
npx vercel dev   # → http://localhost:3000
```

**GitHub Pages або будь-який інший статичний хостинг.** У `assets/app.js` вкажіть у змінній `API_PROXY` повну адресу розгорнутої функції (наприклад, `https://<проєкт>.vercel.app/api/freeserp`) — без цього каталог не завантажиться через помилку CORS на боці API.

## Структура

```
index.html          розмітка чотирьох екранів
api/freeserp.js     функція-посередник до API (Vercel)
assets/app.js       логіка: API-клієнт, маршрути, рендер
assets/styles.css   стилі, адаптив
assets/hero*.jpg    зображення банерів сторінок
assets/og.jpg       картинка для превʼю посилання
PLAN.md             план сайту
robots.txt, sitemap.xml   для пошуковиків
```

## Що не встигли

- Вибір кількох ніш одночасно (API це підтримує повторенням параметра).
- Автотести в репозиторії та CI.
- Скриншоти сайтів — API їх не віддає.

## Що доробили б далі

- Повноцінне SEO: окремі HTML-сторінки розділів і ніш (наприклад, `/image-generation/`) зі справжніми адресами замість `#/…`, згенеровані заздалегідь скриптом з API, з контентом у коді сторінки, власними `title`/описом і повним `sitemap.xml`.
- «Обране» і збережені пошуки, експорт добірки в CSV.
- Графік динаміки нових AI-сайтів, фільтр за технологією (`ai_source`).
- Українська та англійська версії інтерфейсу.
